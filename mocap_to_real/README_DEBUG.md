
### 发现与诊断
1. **正常站立震荡原因 (~0.5Hz 低频摇摆)**:
   分析 `walk_log_20260630_163009.csv` 发现，正常站立时发生了周期约为 2 秒的显著震荡。这是典型的“系统缺少阻尼”且“积分过冲”现象。
   在我们上一个“速度形积分器”架构中，通过积分陀螺仪(`gyro`)数据，**我们在数学上把原本该作为 D(阻尼) 的项变成了 P(比例) 项**。这导致系统没有任何真正的阻尼来衰减机身的惯性摇摆，同时高频积分积累得太久(`decay_rate=0.995`)，进而产生了严重的低频震荡（站立不稳）。
2. **前腿推力问题**:
   参数 `front_thrust_gain=1.2` 导致了大腿（Thigh）摆幅在原始 IK 基础上被强行放大，进而出现了“推力太猛不协调”的现象。

### 修复方案
1. **重写为纯正 `PID` + `泄漏积分(Leaky Integrator)` 架构** (`imu_controller.py`)：
   - 彻底废弃了把角速度和角度混在一起积分的做法。
   - **恢复真正的微分阻尼(D)**: 直接使用 `kd * gyro`，并且为了防止高频噪声导致电机“抽搐”（之前出现过的问题），对阻尼输出进行了严格的硬限幅（最大抖动不超过 `±3mm`）。
   - **比例(P)与积分(I)**: `P` 负责提供即时恢复力，`I` 仅用来消除长期稳态误差（如配重不平衡）。`I` 项保留了缓慢衰减(`decay_rate`)特性以防长尾残留。
   - 这套标准架构让参数意义明确，自然消除了无阻尼带来的低频震荡。

2. **前腿推力 100% 原汁原味回退** (`walk.py`)：
   - 将默认的 `--front-thrust-gain` 从 `1.2` 改回了 `1.0`。
   - 在我们的解耦 IK 数学模型中，当该系数为 `1.0` 时，内部的 1 维牛顿迭代会自动且精确地收敛到与“原始全 IK”完全一致的值。这使得**大腿和小腿的运动完全回归到之前的协调状态**，且无需破坏现有的代码架构。


### 边界跳变震荡修复
1. **死区边界阶跃 (Step jump)**:
   在上一版 `imu_controller.py` 中为了增大恢复力，采用了“硬切断”逻辑 (`if abs(roll) > dz else 0`)。这导致当机器狗角度刚超过 1.5° (0.026 rad) 死区时，P 项和 D 项瞬间从 0 突变到一个非 0 值（瞬间跳变 1~3 毫米）。
2. **引发的高频震荡**:
   这 1~3 毫米的瞬间跳跃会对机身产生巨大的反作用力，将机身推回 1.5° 以内，然后输出又瞬间跳回 0。这导致在死区边缘发生了极高频率的反复横跳（Chatter）。这正是“轻轻的动了一下，它就开始震荡了”的完美解释！
3. **修复**:
   - P 比例项: 恢复使用平滑死区 `_deadzone(val)`，超过 1.5° 的部分从 0 开始平滑增加，保证曲线连续（C0 连续）。
   - D 阻尼项: 引入 `fade_roll` 平滑因子，在刚刚跨越死区的 1° 范围内，阻尼输出从 0% 平滑放大到 100%，彻底消灭任何突跳。


### 诊断: 完美行走后为何突然开始“颠”？
1. **现象再现**:
   日志显示，前 1 秒狗处于完美的零倾角状态（Roll 误差极小，几乎不补偿），走得非常稳健。然而一旦累积了微小的倾角（比如 1~2度），就开始剧烈颠簸，Roll 甚至能飙升到 10度。
2. **定位罪魁祸首: `reactive_kp` (Raibert 反应式补偿)**
   - 在 `gait_controller.py` 中，计算出的 `reactive` 角度（基于狗当前的倾斜）被**无差别地加在了所有腿的大腿外展角(`thigh_roll`/`hip`)上**。
   - **致命问题**: 当一条腿**正踩在地上（支撑相）**时，如果倾角发生变化，系统依然会指挥这条腿往侧边掰。这相当于用电机硬生生地在有摩擦力的地面上**横向横扫（踹地）**。
   - 这就造成了正反馈死循环：稍微偏一点 -> 电机猛踹地 -> 被踹得更偏 -> 电机更猛地踹地 -> 疯狂震荡。这正是为什么“走得好好的突然开始颠”的根本原因。
